  
# What is CI/CD pipeline

ഒരു **CI/CD Pipeline** (തുടർച്ചയായ സംയോജനവും വിന്യാസവും) എന്നത് സോഫ്റ്റ്‌വെയർ ഡെവലപ്‌മെന്റിൽ കോഡ് എഴുതുന്നത് മുതൽ അത് യൂസറിലേക്ക് എത്തുന്നതുവരെയുള്ള പ്രക്രിയ പൂർണ്ണമായും ഓട്ടോമാറ്റ് ചെയ്യുന്ന ഒരു സിസ്റ്റമാണ്. മാനുവൽ ആയി കോഡ് ഡിപ്ലോയ് ചെയ്യുമ്പോഴുണ്ടാകുന്ന തെറ്റുകൾ ഒഴിവാക്കാനും പുതിയ ഫീച്ചറുകൾ വേഗത്തിൽ റിലീസ് ചെയ്യാനും ഇത് സഹായിക്കുന്നു.

**Continuous Integration (തുടർച്ചയായ സംയോജനം)**

- പ്രൊജക്റ്റിൽ വർക്ക് ചെയ്യുന്ന ഡെവലപ്പർമാർ അവരുടെ കോഡുകൾ നിരന്തരം ഒരു സെൻട്രൽ **Repository**-ലേക്ക് (സംഭരണകേന്ദ്രം - ഉദാഹരണത്തിന് GitHub) പുഷ് ചെയ്യുന്നു.
    
      
    
- ഓരോ **Commit** (സമർപ്പിക്കൽ) നടക്കുമ്പോഴും സിസ്റ്റം ഓട്ടോമാറ്റിക് ആയി പുതിയ കോഡ് **Build** (നിർമ്മിക്കുക) ചെയ്യുന്നു.
    
      
    
- കോഡിൽ എററുകൾ ഒന്നുമില്ലെന്നും പഴയ ഫീച്ചറുകൾ ബ്രേക്ക് ആയിട്ടില്ലെന്നും ഉറപ്പുവരുത്താൻ സിസ്റ്റം സ്വയം **Automated Tests** (ഓട്ടോമാറ്റിക് പരിശോധനകൾ) റൺ ചെയ്യുന്നു.
    
      
    
**Continuous Delivery / Deployment (തുടർച്ചയായ വിതരണവും വിന്യാസവും)**

- **Continuous Delivery:** ടെസ്റ്റുകൾ എല്ലാം പാസായ ശേഷം കോഡ് സുരക്ഷിതമായ ഒരു **Staging Environment**-ലേക്ക് (പരീക്ഷണ പരിസ്ഥിതി) മാറ്റുന്നു. ഇവിടെ നിന്നും ലൈവ് ആക്കാൻ ഒരു വ്യക്തിയുടെ മാനുവൽ അപ്രൂവൽ ആവശ്യമാണ്.
    
      
    
- **Continuous Deployment:** ഇവിടെ മാനുവൽ അപ്രൂവൽ ഇല്ല. ടെസ്റ്റുകൾ പാസായ കോഡ് നേരെ യൂസർ ഉപയോഗിക്കുന്ന **Production Environment**-ലേക്ക് (പ്രവർത്തന പരിസ്ഥിതി) ഓട്ടോമാറ്റിക് ആയി ഡിപ്ലോയ് ചെയ്യപ്പെടുന്നു.
    
      
    
**Behind the Scenes (പിന്നണിയിലെ പ്രവർത്തനം)**

നിങ്ങൾ പുതിയ കോഡ് പുഷ് ചെയ്യുമ്പോൾ, നിങ്ങളുടെ വേർഷൻ കൺട്രോൾ സിസ്റ്റം ഒരു **Webhook** (വെബ്ഹുക്ക്) വഴി **CI Server**-ന് (ഉദാഹരണത്തിന് Jenkins അല്ലെങ്കിൽ GitHub Actions) ഒരു സിഗ്നൽ അയക്കുന്നു. ഈ സെർവർ നിങ്ങളുടെ പ്രൊജക്റ്റിലുള്ള ഒരു **Configuration File** (ക്രമീകരണ ഫയൽ - പ്രധാനമായും `.yml` ഫോർമാറ്റിൽ ഉള്ളത്) വായിക്കുകയും, അതിൽ നിർവചിച്ചിരിക്കുന്ന **Jobs** (ജോലികൾ) കൃത്യമായ ഓർഡറിൽ എക്സിക്യൂട്ട് ചെയ്യുകയും ചെയ്യുന്നു. ഇതിൽ ഏതെങ്കിലും ഒരു സ്റ്റെപ്പിൽ (ഉദാഹരണത്തിന് ടെസ്റ്റിംഗിൽ) എറർ വന്നാൽ, പൈപ്പ്‌ലൈൻ അവിടെവെച്ച് നിൽക്കുകയും ഡെവലപ്പർക്ക് നോട്ടിഫിക്കേഷൻ ലഭിക്കുകയും ചെയ്യും.

**Real-World Analogy (പ്രായോഗിക ഉദാഹരണം)**

ഒരു കാർ നിർമ്മാണ കമ്പനിയിലെ അസംബ്ലി ലൈൻ പോലെയാണ് ഇത്. പല തൊഴിലാളികൾ നിർമ്മിക്കുന്ന എഞ്ചിനും ടയറും മറ്റു ഭാഗങ്ങളും ഒരിടത്ത് കൂട്ടിയിണക്കുന്നതാണ് **Continuous Integration**. നിർമ്മിച്ച കാർ കൃത്യമായി സ്റ്റാർട്ട് ആകുന്നുണ്ടോ എന്ന് മെഷീനുകൾ സ്വയം ചെക്ക് ചെയ്യുന്നതാണ് **Automated Testing**. എല്ലാം പെർഫെക്റ്റ് ആണെങ്കിൽ ആ കാർ മാനുവൽ ഇടപെടലുകൾ ഇല്ലാതെ നേരെ ഷോറൂമിലേക്ക് വിൽക്കാൻ അയക്കുന്നതാണ് **Continuous Deployment**. കോഡിൽ എറർ ഉണ്ടെങ്കിൽ (കാറിന് തകരാറുണ്ടെങ്കിൽ) അസംബ്ലി ലൈൻ അവിടെവെച്ച് നിൽക്കും.
