**Software Design Paradigm** എന്നത് ഒരു പ്രശ്നത്തെ (problem) എങ്ങനെ സമീപിച്ച് കോഡ് വഴി സോൾവ് ചെയ്യാം എന്നതിൻ്റെ അടിസ്ഥാന ചിന്താരീതിയാണ് (way of thinking) അല്ലെങ്കിൽ ഒരു architecture style ആണ്. ഇത് ഒരു പ്രത്യേക Programming Language അല്ല, മറിച്ച് കോഡ് സ്ട്രക്ചർ ചെയ്യാനുള്ള ഒരു രീതിശാസ്ത്രമാണ് (methodology).

  
ഒരു വീട് വെക്കുന്നത് പോലെ ചിന്തിക്കുക. വീടിന്റെ ഡിസൈൻ (ഉദാഹരണത്തിന്, മോഡുലാർ ഡിസൈൻ അതോ പരമ്പരാഗത ഡിസൈൻ) ആണ് Paradigm. വീട് വെക്കാൻ ഉപയോഗിക്കുന്ന സിമന്റും ഇഷ്ടികയും ഒക്കെയാണ് Programming Languages. ഒരേ സിമന്റ് ഉപയോഗിച്ച് പല ഡിസൈനിൽ വീട് വെക്കാം. അതുപോലെ ഒരേ ഭാഷ (ഉദാഹരണത്തിന് TypeScript അല്ലെങ്കിൽ JavaScript) ഉപയോഗിച്ച് പല Paradigms-ൽ കോഡ് എഴുതാം.

പ്രധാനമായും 4 തരത്തിലുള്ള Software Design Paradigms ആണ് ഉള്ളത്:
### 1. Imperative Programming

ഒരു കാര്യം **എങ്ങനെ ചെയ്യണം (How to do)** എന്ന് കമ്പ്യൂട്ടറിന് ഓരോ സ്റ്റെപ്പായി കൃത്യമായ നിർദ്ദേശങ്ങൾ കൊടുക്കുന്ന രീതിയാണിത്.

- **Analogy:** ഒരു സുഹൃത്തിന് വഴി പറഞ്ഞുകൊടുക്കുന്നത് പോലെ - "നേരെ പോവുക, സിഗ്നൽ എത്തുമ്പോൾ വലത്തോട്ട് തിരിയുക, 50 മീറ്റർ പോവുക".
    
      
    
- **Under-the-hood:** ഇവിടെ കമ്പ്യൂട്ടറിന്റെ മെമ്മറിയിലുള്ള ഡാറ്റ (State) ഇടയ്ക്കിടെ മാറിക്കൊണ്ടിരിക്കും. Control Flow, Loops, Variables എന്നിവ ഉപയോഗിച്ച് കമ്പ്യൂട്ടറിന്റെ മെമ്മറി എങ്ങനെ അപ്ഡേറ്റ് ചെയ്യണം എന്ന് നമ്മൾ കൃത്യമായി പറയുന്നു.
    
      
    
### 2. Declarative Programming

നമുക്ക് **എന്ത് റിസൾട്ട് ആണ് വേണ്ടത് (What to do)** എന്ന് മാത്രം പറയുന്ന രീതിയാണിത്. അത് എങ്ങനെ ചെയ്യണം എന്നത് സിസ്റ്റം തനിയെ തീരുമാനിക്കും.

- **Analogy:** ടാക്സി ഡ്രൈവറോട് "എനിക്ക് എയർപോർട്ടിൽ പോണം" എന്ന് പറയുന്നതുപോലെ. ഏത് വഴി പോവണം എന്ന് ഡ്രൈവർ സ്വന്തമായി തീരുമാനിക്കും.
    
      
    
- **Practical Context:** Next.js അല്ലെങ്കിൽ React ഉപയോഗിച്ച് UI ഡിസൈൻ ചെയ്യുമ്പോൾ നമ്മൾ Declarative രീതിയാണ് ഉപയോഗിക്കുന്നത്. സ്ക്രീനിൽ എന്ത് കാണണം എന്ന് നമ്മൾ പറയുന്നു, DOM manipulation (അത് സ്ക്രീനിൽ എങ്ങനെ അപ്ഡേറ്റ് ചെയ്യണം എന്നത്) React സ്വയം ചെയ്തുകൊള്ളും. അതുപോലെ SQL ഉപയോഗിച്ച് ഡാറ്റാബേസിൽ നിന്ന് ഡാറ്റ എടുക്കുന്നതും Declarative ആണ്.
    
      
    
### 3. Object-Oriented Programming (OOP)

സിസ്റ്റത്തിലുള്ള കാര്യങ്ങളെ Objects ആയി കണക്കാക്കി കോഡ് എഴുതുന്ന രീതി. ഒരു Object-ൽ അതിൻ്റെ ഡാറ്റയും (Properties) ആ ഡാറ്റയിൽ പ്രവർത്തിക്കുന്ന ഫംഗ്ഷനുകളും (Methods) ഒരുമിച്ച് ചേർത്തിട്ടുണ്ടാകും.

- **Analogy:** ഒരു കാർ. കാറിന് ചില properties ഉണ്ട് (കളർ, മോഡൽ), അതുപോലെ ചില functions ഉണ്ട് (സ്റ്റാർട്ട് ചെയ്യുക, ബ്രേക്ക് പിടിക്കുക).
    
      
    
- **Core Concepts:** Classes, Objects, Inheritance (മറ്റൊരു ക്ലാസ്സിൽ നിന്ന് ഫീച്ചറുകൾ എടുക്കുക), Encapsulation (ഡാറ്റ സുരക്ഷിതമായി ഒളിപ്പിച്ചു വെക്കുക). Node.js backend-ൽ ഡാറ്റാബേസ് മോഡലുകൾ ഡിസൈൻ ചെയ്യുമ്പോൾ നമ്മൾ OOP ശൈലിയാണ് കൂടുതലും ഉപയോഗിക്കുന്നത്.
    
      
    
### 4. Functional Programming

സോഫ്റ്റ്‌വെയറിനെ വെറും mathematical functions ആയി കണ്ട് കോഡ് ചെയ്യുന്ന രീതി. ഇവിടെ ഡാറ്റ ഒരിക്കലും മാറ്റം വരുത്താൻ പാടില്ല (Immutability). ഒരു ഡാറ്റ മാറ്റണമെങ്കിൽ, നിലവിലുള്ള ഡാറ്റ വെച്ച് പുതിയൊരു ഡാറ്റ ഉണ്ടാക്കുകയാണ് ചെയ്യുന്നത്.

- **Core Concepts:** Pure Functions (എപ്പോഴും ഒരേ ഇൻപുട്ടിന് ഒരേ ഔട്ട്പുട്ട് തരുന്ന ഫംഗ്ഷനുകൾ), Immutability, First-Class Functions.
    
      
    
- **Practical Context:** Redux ഉപയോഗിച്ച് state management ചെയ്യുമ്പോൾ ഈ ശൈലിയാണ് കർശനമായി പിന്തുടരുന്നത്. Redux-ലെ Reducer functions എപ്പോഴും Pure Functions ആയിരിക്കും, അവ നിലവിലെ state നേരിട്ട് mutate ചെയ്യാതെ പുതിയ state റിട്ടേൺ ചെയ്യുന്നു.
    
      
    
**Conclusion:**

ഒരു പ്രോജക്റ്റിൽ ഇതിൽ ഏതെങ്കിലും ഒരു Paradigm മാത്രം ഉപയോഗിക്കണം എന്ന് നിർബന്ധമില്ല. മിക്ക ആധുനിക ആപ്ലിക്കേഷനുകളും (Multi-paradigm approach) ഒന്നിലധികം Paradigms ഒരുമിച്ച് ചേർത്താണ് നിർമ്മിക്കുന്നത്. ഉദാഹരണത്തിന്, View layer Declarative ആയും, Data models OOP ആയും, State management Functional ആയും ഒരുമിച്ച് പ്രവർത്തിക്കുന്നു.
